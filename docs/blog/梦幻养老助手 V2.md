## 缘起

玩梦幻的人大概都遇到过这种时刻：这个月到底赚了多少，说不清；几件装备各花了多少，也说不清；想练个角色，师门技能点到几级了，还是说不清。

表格能记，但记不细。物品得按当前物价估值，点卡要按在线时长摊到每个号头上，装备有十二个格子，还分常规、灵饰、玉魄。

所以就自己写了一个。

![梦幻养老助手总览](images/mh-tool-overview.webp)

## 它是什么

一个 Windows 桌面应用，Electron 38 + Vue 3 + TypeScript + Pinia，八个页面，覆盖从记一笔收益到配一套装备。

| 页面 | 用来做什么 |
|------|------------|
| 总览 | 收益、账号、目标三块汇总，14 天零轴趋势，最近记录 |
| 收益 | 物品速记，点一下记一条并按当前物价估值；在线计时，多开按人头分摊点卡；按天分账 |
| 账号 | 人民币与梦幻币分账，快捷记账，全部记录筛选与 CSV 导出 |
| 目标 | 养成目标跟随档案自动累计；存钱与装备目标手动记进度 |
| 装备 | 三套方案，12 个格子（常规 6 + 灵饰 4 + 玉魄 2），仓库、结构化属性、截图识别 |
| 角色 | 档案、师门与辅助技能、人物与召唤兽修炼、门派模板、转门派 |
| 物价 | 九个一级分类、三十七个二级，卡片式行情与价格流水 |
| 设置 | 三档外观、JSON 备份导入导出、使用帮助、检查更新 |

有一点是刻意设计的：数据不登录、不上传，断网也能用。所有东西都在 `%APPDATA%/mh-tool-v2/data.json` 里，不在安装目录，所以升级不会丢；换机器拷这一份 JSON 就够。

![收益页：物品速记与在线计时](images/mh-tool-income.webp)

## 三个不显眼的选择

这个项目真正花时间的，不是页面好不好看，而是几个用户永远看不到的地方。

### 一、写盘永远走临时文件

记一笔账→存到磁盘，听起来是一行代码。但如果写到一半断电，或者进程被杀，`data.json` 就成了半截 JSON，整个账本打不开。

所以每次保存都是：写临时文件，再 `rename` 覆盖目标。重命名在同一分区上是原子的，要么是旧文件，要么是新文件，没有中间状态。

在此之上还有几层保险：普通保存保留 3 份滚动备份；导入、清空、换版本之前另存一份事务备份；磁盘上的数据版本高于当前版本时拒绝覆盖，避免用旧程序把新数据降级写坏。

数据版本和应用版本是分开的两个号。应用现在是 `0.3.0`，数据格式已经是 `9`，升级过一次计时模型——从「同时只有一段在线会话」改成「每个角色各一段」，各自起停。

### 二、界面拿到的永远是快照

Electron 应用里最容易写坏的，是状态。Vue 的响应式对象经不起到处改，一深拷贝又丢引用，最后没人说得清某个数字是谁改的。

这里的做法是把状态切成两份：

- 领域实例持有唯一可写业务状态，放在 Vue 代理之外；
- Pinia 里只有操作完成后的普通快照，界面只读，组件不直接改快照；
- 所有写入走领域的串行 commit 队列，事务内读最新状态、改完落盘，失败就恢复整个内存快照。

好处是「撤销」和「回滚」变成了同一件事。做完成或回滚，重新发布一次快照，界面自然跟上。

顺带一个细节：IPC 传的一律是普通对象。Vue 代理没法结构化克隆，直接传过去会在主进程那头炸掉。

### 三、识别截图这种事不进主进程

装备截图识别是这个项目最重的一块。OCR 模型跑一次能把 CPU 吃满十几秒，如果放在主进程，消息循环会卡住，连带保存也卡住。

所以它被隔离在 `utilityProcess` 子进程里：一次一张，单张 45 秒超时，空闲 60 秒自动退出。渲染层只发一个 dataURL，主进程用 `nativeImage` 校验格式、体积、像素之后交给子进程，图片不落盘，回来的只有一段文本。

文本再交给渲染层的解析器拆部位、词条、玉魄。关键在于——它和「粘贴导入」走的是同一条解析链路，所以两条入口的规则不会各走各的。

## 一些妥协

说几个自己不太满意、但权衡后接受的地方。

打包体积。OCR 依赖 `@gutenye/ocr-node`、`onnxruntime-node`、`sharp` 和模型文件，解包后 361MB。已经排掉了 DirectML、只留中英文语言包，再往下砍就要牺牲识别能力，暂时到此为止。

首屏体积。主 chunk 贴着 Vite 500 kB 的告警线（约 492 kB）。所以成篇的长文案一律走异步组件，使用教程近万字就是这么拆出去的——同步 import 会把它全压进首屏。

外链。窗口拒绝了所有 `window.open`，`will-navigate` 一律拦截，界面上点不动任何外链。这是安全换来的：外链只能走主进程的白名单接口，只放行 `https` 且域名是 `github.com` 或 `polyformproject.org` 的地址。

检查更新也一样克制。只读不写：拉 GitHub 的 Release 订阅源比版本号，不下载、不安装、不落盘。用 `releases.atom` 而不是 API，是因为匿名调 API 按出口 IP 每小时只有 60 次，挂代理时经常早被别人打满。

## 装来用

需要 Node 22.12 以上。

```bash
git clone https://github.com/zhijian521/mh-toolbox.git
cd mh-toolbox
npm ci
npm run dev
```

想直接装：到 Releases 下载安装版或便携版。也可以用新包覆盖安装，两种装法共用同一份数据。

本地打包：

```bash
npm run dist        # 安装版 + 便携版，输出到 release/
npm run dist:dir    # 只出免安装目录
```
